## Задача 1

### Текст задачи

Заполнение двумерных массивов.
Первый массив, размерностью n х m, заполняется данными, вводимыми с клавиатуры, так что
заполнение ведется по строкам от последних элементов строки к первым.
Второй массив, размерностью n х n, заполняется так: элементы, лежащие ниже главной
диагонали, являются случайными числами из интервала [-17;36], а лежащие на главной
диагонали и выше, являются случайными числами из интервала [100; 10000].
Третий массив, размерностью n х n, заполняется для произвольного n так же, как для n=5:
11 0 0 0 0 
7 12 0 0 0 
4 8 13 0 0
2 5 9 14 0
1 3 6 10 15

### Алгоритм решения
1. Создан класс Matrix, единственное поле - двумерный массив _data. Конструкторы: по умолчанию (пустой массив), из готового массива, копирования, и три конструктора для задания 1: (int rows, int cols) с вводом с клавиатуры, где заполнение ведется по строкам от последних элементов строки к первым (цикл по j от cols - 1 до 0); (int size, int minBelow, int maxBelow, int minAbove, int maxAbove) со случайным заполнением, где элементы ниже главной диагонали (i > j) берутся из интервала [-17;36], а лежащие на диагонали и выше из [100;10000]; (int size) с автоматическим заполнением по узору для произвольного n: счетчик идет по диагоналям, параллельным главной, от нижней левой к главной диагонали, а выше главной диагонали остаются нули. И перегруженный метод ToString, который собирает таблицу: таб в начале строки и PadLeft(6), чтобы столбцы были ровненькими
2. В методе SolveTask1 пользователь вводит n строк и m столбцов массива 1 (проверка на положительное число через ReadPositiveInt), массив 1 создается конструктором с вводом с клавиатуры и выводится на экран. Затем вводит n для массивов 2 и 3: массив 2 создается конструктором со случайными значениями (границы -17, 36, 100, 10000 передаются параметрами), массив 3 конструктором с узором, размерность как у массива 2. Оба выводятся через ToString

### Текст задачи

Бинарные файлы.
Получить в новом файле те компоненты исходного файла, которые являются четными.

### Алгоритм решения
1. В статическом классе Files созданы методы заполнения бинарного файла: FillBinaryFileAuto (записывает count случайных чисел в диапазоне [min; max] через BinaryWriter) и FillBinaryFileManual (каждое число спрашивает с клавиатуры). Оба возвращают bool: true если файл создан успешно и false если ошибка (все внутри try-catch, чтобы программка не падала, если файл занят или удален). Метод ReadBinaryFile читает файл за один проход: количество элементов вычисляется из размера файла, деленного на 4, тк один int занимает ровно 4 байта
2. Метод FilterEvenBinary открывает исходный файл на чтение и новый на запись (BinaryReader и BinaryWriter внутри using, чтобы файлы закрылись автоматически), читает числа по одному и переписывает в новый файл только четные (проверка num % 2 == 0), возвращает их количество
3. В SolveTask4 пользователь выбирает способ заполнения и сколько чисел записать, для случайного вводит границы (проверка min <= max в цикле while). Если файл не создался (метод вернул false), выводится сообщение и задание прерывается. Иначе выводится исходный файл массивом, вызывается FilterEvenBinary и выводится файл-результат; если четных не оказалось, так и пишется

# Задание 5

## Задача 1

### Текст задачи

Бинарные файлы и структуры.
Информация о багаже пассажира описывается массивом, где каждый элемент содержит название
единицы багажа (чемодан, сумка, коробка и т.д.) и ее массу. Дан файл, содержащий сведения о
багаже нескольких пассажиров. Найти багаж, средняя масса одной единицы багажа, в котором
отличается не более чем на m кг от общей средней массы одной единицы багажа.

### Алгоритм решения
1.В классе Files созданы структуры: LuggageItem (название единицы багажа и ее масса) и PassengerLuggage (имя пассажира и массив его единиц багажа). На них повешены атрибуты [XmlElement], [XmlArray] и [XmlArrayItem], чтобы работала XML-сериализация
2. Заполнение исходного файла: FillLuggageFileAuto (каждому пассажиру случайное количество единиц от 1 до 4, названия из списка, массы от 1 до 25 кг с округлением до десятых) и FillLuggageFileManual (пользователь вводит имя пассажира, количество единиц и для каждой название и массу, масса проверяется на больше нуля в цикле while). Оба вызывают приватный метод SaveLuggage, который через XmlSerializer переводит массив структур в XML и записывает в файл, это и есть обязательная сериализация
3. Метод FindLuggageByAverage читает файл обратно через ReadLuggageFile (десериализация). Сначала считает общую среднюю массу одной единицы: сумма всех масс делится на количество всех единиц всех пассажиров. Затем для каждого пассажира считает его среднюю массу (его сумма делится на его количество единиц) и сравнивает с общей: если разница через Math.Abs не больше m, пассажир выводится, иначе в конце пишется что подходящего багажа нет
4. Пользователь выбирает способ заполнения и количество пассажиров, содержимое файла выводится через PrintLuggage, затем вводится m (проверка m > 0 в цикле while) и выводится решение

# Задание 8

### Текст задачи

Текстовый файл.
Переписать в другой текстовый файл самую короткую и самую длинную строки

### Алгоритм решения
1. В классе Files созданы методы FillTextFileByLines (пользователь вводит непустые строки, проверка через ReadNonEmptyString) и FillTextFileByWords (каждая строка собирается из случайного количества слов от 2 до 6 из списка, чтобы строки гарантированно были разной длины)
